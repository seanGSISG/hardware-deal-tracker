### Lessons Learned
- The scoring engine's `bulk_score`/`per_unit` block was half-built: it computed a bulk bonus on per-unit but still judged z-score/discount/scam-floor on the **lot total**, so lots could never score well. Lighting up "lot support" needed the parser to set quantity AND the main components to normalize per-unit — not just the parser.
- `hdt-backend` bakes code into the image (no bind-mount), so source edits require `docker compose build backend && up -d backend` to go live — a plain restart runs stale code.
- Browse API = active asks only; sold comps need approval-gated Marketplace Insights. Active-ask-anchored prices run high — re-anchor once sold access lands.

### Lessons Learned
- `seed_data_v2.sql` is GENERATED from `catalog.py` — never hand-edit; `make seed-regen` (`uv run scripts/generate_seed.py`) is the only path. `min_deal_score`/`pcpp_product_id` are stamped at import time, so the catalog stays the single source of truth.
- Adding N memory SKUs is API-budget-bound: each item at interval S adds 86400/S calls/day against eBay's 5k/day cap — pick the poll tier from the budget, not the item's volatility.

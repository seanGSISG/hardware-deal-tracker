# Session 2 — Enabled Shopify sources; live re-verification found 3 of 6 stores dead/blocked

- **Found Shopify ingestion was silently OFF** — `ENABLE_SHOPIFY_SOURCES` was never set in the deployed `project/.env`, so it fell back to the config default `False`. Confirmed in the running container: `settings.ENABLE_SHOPIFY_SOURCES = False`. eBay was the only live source.
- **Root cause of "flag won't take" — compose env allowlist** — the `backend` service uses an explicit `environment:` map (not `env_file:`), so adding a var to `.env` alone does nothing; it must also be referenced as `${VAR}` in `docker-compose.yml`. Two `--force-recreate` cycles showed `False` until the var was added to the compose env block.
- **Live re-verification: registry's 2026-06-02 "verified" status had rotted** — probed each store's `/products.json` from the Spark host:
  - LIVE: cloud_ninjas (200), savemyserver (200), techmikeny (**only via `www.` — apex 404s**)
  - BROKEN: unixsurplus (404, endpoint removed), servermonkey (403 bot-block), natex (000, domain SERVFAIL/dead)
- **Enabled the 3 working stores, cleanly disabled the 3 broken ones** — `.env`: `ENABLE_SHOPIFY_SOURCES=true`, `SHOPIFY_TECHMIKENY_BASE_URL=https://www.techmikeny.com`, and `*_ENABLED=false` for unixsurplus/servermonkey/natex; forwarded all through the compose allowlist. Verified active adapters = `[techmikeny, cloud_ninjas, savemyserver]`, each fetching 750 products live with no errors.
- **0 catalog matches at enablement is expected, not a bug** — strict per-SKU all-token matching against the 34-item catalog; the stores stock bare EPYCs (7452/7551P/9334…) but none of the exact 34 tracked models are in stock right now. Pipeline (fetch→parse→match) is fully working.
- **Docs updated** — `project/backend/docs/SOURCE_ROADMAP.md` source-status row + new "Shopify re-verification — 2026-06-30" section with the per-store table and a re-onboarding follow-up.

### Lessons Learned
- **"Verified once" ≠ "verified now" for external scraped sources.** Shopify `/products.json` endpoints rot fast — stores move to `www.`, disable the JSON endpoint, add bot-blocks, or let domains lapse. The robots/ToS verification in the registry needs a periodic live re-probe, not a one-time stamp. Worth a scheduled health-check that flips per-store flags automatically.
- **This repo's backend compose uses an `environment:` allowlist, not `env_file:`** — every new backend setting must be added to `docker-compose.yml` to reach the container, even if it's already in `.env`.
